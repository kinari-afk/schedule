# schedule

訪問担当表（CareRoute）

`index.html` 1ファイルで動く、訪問看護のスケジュール作成アプリです。データは Firebase（Firestore）に保存されます。

---

## 1. はじめに必ず行う設定（セキュリティ）

このリポジトリは公開されています。**コードに書いてあるものは誰でも読める**前提で、次の設定を行ってください。

### 手順A：管理者ログインを有効にする

1. [Firebase コンソール](https://console.firebase.google.com/) で対象のプロジェクトを開く
2. 「Authentication」→「Sign-in method」→「メール / パスワード」を**有効**にする
3. 「Authentication」→「Users」→「ユーザーを追加」で、管理者用のメールアドレスとパスワードを登録する
4. アプリを `…/index.html?mode=admin` で開き、登録したメールアドレスとパスワードでログインできることを確認する

> `?mode=admin` は「ログイン画面を出す」だけの合図になりました。これを付けただけでは編集できません。
> 一度ログインすると、その端末ではログイン状態が保たれます（サイドバーの「ログアウト」で解除）。

### 手順B：データベースのルールを設定する（これが本当の鍵）

画面上のボタンを隠すだけでは、技術のある人の書き込みを防げません。実際に守るのは Firestore の「ルール」です。

「Firestore Database」→「ルール」を開き、**今のルールを控えたうえで**、次の内容に置き換えて「公開」します。
`admin@example.com` は手順Aで登録した管理者のメールアドレスに書き換えてください。

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /artifacts/{appId}/public/data/{collection}/{docId} {
      // 閲覧：アプリを開いた人（匿名ログイン）なら誰でも
      allow read: if request.auth != null;
      // 編集：下のメールアドレスでログインした管理者だけ
      allow write: if request.auth != null
                   && request.auth.token.email in ['admin@example.com'];
    }
  }
}
```

管理者を複数にする場合は `['a@example.com', 'b@example.com']` のように並べます。

> メールアドレスを名指しにしているのは、「メール / パスワード」ログインを有効にすると、
> 第三者が勝手にアカウントを作ること自体は防げない場合があるためです。名指しにしておけば、
> 勝手に作られたアカウントでは書き込めません。

### 手順C（任意・推奨）：閲覧にもログインを必須にする

手順Bまでの状態では、**アプリのURLを知っている人は誰でも利用者名や住所を閲覧できます。**
閲覧も制限したい場合は次のようにします。

1. 手順Aと同じ方法で、スタッフ共用の閲覧用アカウント（例：`staff@example.com`）を作る
2. `index.html` の上のほうにある設定を書き換える

   ```js
   const REQUIRE_LOGIN_TO_VIEW = true;
   const ADMIN_EMAILS = ['admin@example.com'];   // 管理者だけを書く
   ```

3. ルールの `allow read` を次のように変える

   ```
   allow read: if request.auth != null
               && request.auth.token.email in ['admin@example.com', 'staff@example.com'];
   ```

スタッフは初回だけログインが必要になり、以後はその端末で開けば見られます。

### 手順D：利用者スプレッドシートのURLを作り直す

以前のバージョンでは、利用者・看護師スプレッドシートの公開URLがコードに直接書かれていました。
コードからは削除しましたが、**過去の履歴には残っており、URL自体も有効なまま**です。

1. 元のスプレッドシートを「コピーを作成」で複製する
2. 複製したほうを「ファイル → 共有 → ウェブに公開」でCSVとして公開し、新しいURLを得る
3. アプリの「利用者管理」「看護師管理」→「接続設定」に新しいURLを貼る
4. 元のスプレッドシートの「ウェブに公開」を**停止**する

> 「ウェブに公開」したCSVは、URLを知っていれば誰でも読めます。手順Cまで行っても、
> このURLが漏れれば利用者情報は読まれてしまう点にご注意ください。

| 5 | 限定 | 女性 |

| 10 | 状態 | 休止 |

### 看護師

| 列 | 内容 |
|---|---|
| 1 | 氏名 |
| 2・3 | 勤務開始・終了時間 |

看護師は**名前**で同一人物かを判断します。名前を変えると別人として扱われ、その人の割り当ては「未割り当て」に戻ります。

## 3. 移動時間の計算

移動時間 ＝「基本の移動時間（分）」＋ 距離に応じた時間 です。距離の分は、分かっている情報に応じて次の順で決まります。

1. **緯度・経度が両方の地点で分かる** … 直線距離 × 1.3（道のり換算）÷ 時速
2. **町名だけ分かる** … 同じ町名なら +0分、違えば +4分
3. **どちらかが不明** … +2分

緯度・経度は、シートに書くか、「利用者管理」の「住所から位置を取得する」ボタンで取得できます。
このボタンは国土地理院の住所検索サービスに**住所だけ**を送ります（氏名は送りません）。

個々の区間の移動時間は、これまでどおり画面上で手入力して上書きできます。

## 4. データの保管とバックアップ

- 予定は1つの保存枠（上限 約1MB）にたまります。使用量は「集計レポート」で確認できます。
- 「古いデータを保管庫へ移す」で、直近6か月より前の月を月別の保存枠に移せます。
  移した月は上限の対象から外れ、その日付を開けば閲覧できます（編集するときは「編集できるように戻す」）。
- 「バックアップを保存」で、保管庫を含む全データを1つのファイルとして端末に保存できます。
- 「バックアップから復元」は、いまのデータをファイルの内容で**すべて置き換えます**。
  実行前に、その時点の状態を自動でファイル保存します。

バックアップファイルには利用者の個人情報が含まれます。保管場所にご注意ください。

## 5. スマホでの編集

ドラッグ操作はスマホでは使えないため、管理者としてログインした状態でカードをタップし、
メニューの「担当者・時間を変更」から変更します。担当者の一覧には、その時間が「空き」か「重複」か、
選べない理由（お休み・女性限定など）が表示されます。

---

## 自動編成の使い方

- **自動編成**：表示中の1日分を割り当てます。
- **週まとめて編成**：表示中の週のうち、今日以降で未割り当てが残っている日をまとめて割り当てます。「元に戻す」1回で全体を取り消せます。
- **編成の設定**：昼休憩（時間帯と長さ）と、半休の時刻を変更できます。
- **理由の確認**：カードのメニューを開くと、割り当て済みの予定には「なぜその人になったか」、未割り当ての予定には「誰に入れられて、誰に入れられないのか」が表示されます。割り当て理由は、その画面で自動編成を実行した分だけ表示されます（再読み込みすると消えます）。
- **負担の一覧**：担当者ごとに、その日の訪問・会議など・移動の時間と、勤務時間に対する割合を並べて表示します。平均より15ポイント以上離れると「多め」「少なめ」が付き、時間外や休憩なしも表示されます。右端はその週の訪問の合計です。
- **未割り当ての一覧**：「未割り当て ○件」の赤い数字を押すと一覧が開き、行を押して続けて割り当てできます。

昼休憩は、取れる人を優先して割り当てます。全員が取れなくなる場合でも未割り当てにはせず、
割り当てたうえで担当者名の下に「休憩なし」と表示します。

## 6. 印刷・PDF

「全体スケジュール」または「個別ルート確認」の「印刷 / PDF」ボタンを押すと、印刷用の表が開きます。
PDFにしたいときは、印刷画面の送信先（プリンター）で「PDFに保存」を選びます。

- 全体スケジュールから：その日の全員分（担当者ごとの一覧、未割り当て、お休みの人、共有事項）
- 個別ルート確認から：選んでいる担当者の分だけ（住所とコメント付き）

---

## 7. 同行訪問

カードのメニューの「同行複製」で作った予定は、元の予定とつながっています。

- 元の予定の時刻・日付・所要時間を変えると、同行予定も同じだけ動きます
- 元の予定を削除すると、同行予定も削除されます（「元に戻す」で両方戻ります）
- 同行予定だけを動かした場合は、そのずれを保ったまま連動します
- 自動編成では、時間が重なるため主担当とは別の人に割り当てられます

---

## 8. 電波がない場所での表示

一度アプリを開いた端末では、電波がなくても最後に読み込んだ内容を表示できます。
画面上部に「オフラインです」と出ている間は閲覧のみで、編集は電波が戻ってからになります。

- アプリ本体の保存は `sw.js` が、予定データの保存は Firebase の仕組みが行います。**`sw.js` は `index.html` と同じ場所に置いてください**
- 表示されるのは「最後に電波のある場所で開いたとき」の内容です。訪問に出る前に一度開いておくと確実です
- 共用の端末では、端末に利用者情報が残る点にご注意ください（ブラウザの「サイトデータを削除」で消せます）

## 9. テスト

`tests/` フォルダに、アプリが正しく動くかを自動で確かめるテストがあります。
アプリ本体の動作には不要で、`index.html` を書き換えたあとの確認に使います。
本物のデータベースや外部サービスにはつながりません（偽物に差し替えて動かします）。

```bash
cd tests
```

計算ロジックのテスト（自動編成・同期の突き合わせ・CSVの読み取り・移動時間など）。追加のインストールは不要です。

```bash
npm test
```

画面を実際に操作するテスト（ログイン・自動編成・同期・保管庫・復元・スマホ操作）。初回だけ準備が必要です。

```bash
npm install
```

```bash
npx playwright install chromium
```

```bash
npm run test:e2e
```

オフライン表示のテスト（実際に通信を止めて、開き直しても表示されるかを確認）。

```bash
npm run test:offline
```

最後に `ALL PASS` と出れば合格です。画面の写真は `tests/shots/` に保存されます。
